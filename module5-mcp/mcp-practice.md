# MCP 활용 실습

> 🎯 두 MCP로 "AI 혼자서는 절대 답할 수 없는 질문"을 던져봅시다! (15분)

## 실습 1: aws-docs — AWS 공식 문서 조회

AI가 **최신 공식 정보**를 직접 찾아오는 걸 체험해봅시다.

### 질문 1: 서비스 개요

```
aws-docs에서 Amazon Bedrock이 뭔지 공식 문서 기준으로 요약해줘
```

### 질문 2: 실무 연결 질문

```
aws-docs에서 S3 버킷의 데이터 접근 권한을 안전하게 관리하는 방법을 찾아서 정리해줘
```

> 💡 AI가 "공식 문서에 따르면..." 이라는 근거를 들며 답하면 `aws-docs` MCP가 정상 작동하는 것입니다!

## 실습 2: product-db — 사내 제품 DB 직접 조회

이 질문들은 AI가 학습한 지식만으로는 **절대 답할 수 없는** 질문입니다. 우리 회사만의 데이터니까요.

### 질문 3: 브랜드별 현황

```
product-db에서 브랜드별 제품 수와 평균 가격을 조회해서 정리해줘
```

### 질문 4: 티어(등급)별 분석

```
product-db에서 티어(tier)별 평균 가격을 조회해줘.
어느 티어가 제품 수가 가장 많은지도 알려줘.
```

### 질문 5: 실무형 질문 (NPL 프로젝트와 연결)

```
product-db에서 40대 이상 여성을 타겟으로 한 프리미엄 티어 제품을 모두 조회해줘.
가격이 높은 순으로 정리해줘.
```

> 🧴 앞으로 LG생활건강 NPL 프로젝트에서는 이런 사내 데이터 조회가 신제품 기획·가격 포지셔닝 분석에 바로 활용될 예정입니다.

> 💡 AI가 실제 숫자와 제품명을 근거로 답하면 성공! MCP 없이는 AI가 "그런 DB는 접근할 수 없습니다"라고 답했을 질문들입니다.

## 💡 MCP의 핵심 가치

| 구분 | MCP 없이 | MCP 있으면 |
|------|----------|------------|
| aws-docs 질문 | 학습 시점 기준의 부정확한 답변 가능 | **공식 문서 원문** 기반 답변 |
| product-db 질문 | "그 데이터는 접근할 수 없습니다" | **실제 DB 값**으로 정확히 답변 |
| 신뢰도 | 검증 어려움 | 출처가 명확해서 **검증 가능** |

## 🔮 앞으로의 가능성

> MCP는 오늘 연결한 문서·DB뿐만 아니라 **다양한 외부 시스템**을 연결할 수 있습니다:

| MCP 종류 | 활용 예시 |
|----------|-----------|
| 공식 문서 | AWS, 사내 규정, 법규 문서 조회 (오늘 실습) |
| 사내 DB | 제품/매출/재고 데이터 직접 조회 (오늘 실습) |
| PLM 시스템 | 제품 개발 단계/스펙 실시간 조회 |
| 시장 데이터 API | 실시간 트렌드/경쟁사 동향 수집 |
| Slack/Teams | 분석 결과를 팀 채널로 자동 전송 |

> 🧴 **NPL 프로젝트에서의 활용**: 오늘 사내 제품 DB를 연결해본 것처럼, 향후 PLM 시스템·매출 데이터·시장 데이터를 MCP로 연결하면 AI가 여러 사내 시스템을 넘나들며 NPL Report를 자동 작성할 수 있습니다!

## 🔧 트러블슈팅

### "aws-docs 검색 결과가 안 나와요"

* 인터넷 연결 확인
* 질문을 더 구체적인 AWS 서비스명으로 바꿔보세요

### "product-db 조회가 안 돼요"

* `data/lghh_products.db` 파일이 있는지 확인 ([MCP 설정하기](setup-mcp.md) Step 1을 먼저 완료했는지 확인)
* MCP 서버 상태가 "Connected"인지 확인

### "응답이 너무 오래 걸려요"

* 최초 연결 시 10~30초 정도 소요될 수 있습니다
* 인터넷 연결 상태 확인
